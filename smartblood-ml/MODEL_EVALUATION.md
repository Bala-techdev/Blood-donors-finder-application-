# SmartBlood AI model evaluation

Generated by `evaluate_models.py` from the repository's current artifacts.
The response dataset is synthetic demonstration data. None of these metrics
are evidence of real-world donor behavior or production effectiveness.

## Response prediction

| Item | Current implementation |
|---|---|
| Target | `responded`: whether an invited donor response was recorded |
| Data source | `data/donor_response_dataset.csv`, generated by `create_dataset.py` |
| Dataset size | 2,000 rows: 1,972 positive and 28 negative labels |
| Input features | `blood_compatible`, `distance_km`, `available`, `eligible`, `verified`, `total_donations`, `previous_recommendations`, `previous_acceptances`, `previous_declines`, `response_rate`, `acceptance_rate`, `urgency_score` |
| Preprocessing | Numeric fields are range-validated by FastAPI; no imputation or scaling |
| Model | Calibrated Random Forest, 100 trees, balanced subsampling, sigmoid calibration |
| Version | `response-rf-calibrated-v1` |
| Split | Stratified 80/20 holdout, `random_state=42`; calibration uses 3-fold CV inside training data |
| Leakage check | The target is excluded from features; response timestamps/durations are absent; no final response outcome is sent to the endpoint |

The evaluation script reports both the majority-class baseline and model
metrics on the held-out 20%. It never reports training-set performance as
test performance.

The model does not improve the majority baseline's F1 on this holdout. These
results are synthetic-data demonstration results only. The exact metrics are
produced by `evaluate_models.py` and should be regenerated rather than copied
into deployment claims.

Limitations:

- The labels and feature relationships are synthetically generated.
- The labels are severely imbalanced.
- There is no donor-level chronological history, so this is not a temporal
  generalization test.
- `eligible` and `available` are valid recommendation-time gates in the
  application, but the synthetic generator does not represent real donor
  operations.
- Calibration quality is measured by Brier score only; no production
  calibration study exists.

Spring Boot calls `/predict` through `MlPredictionService`; the result is
only a ranking input after compatibility, availability, and eligibility
filters. React displays the probability as a model estimate, not medical
clearance.

## Response-time estimation

No response-time model exists and no metrics are reported. The dataset has no
`recommended_at`, `responded_at`, response status, observation end, or
censoring fields. The database entity has recommendation/response timestamps,
but they have not been exported into training data.

The correct target would be elapsed minutes from `recommendedAt` to a recorded
`ACCEPTED` or `DECLINED` response. Missing responses are right-censored, not
zero-minute responses. A future evaluation should use a chronological split,
MAE/median absolute error for observed durations, and a survival metric/model
when censoring is material.

See [RESPONSE_TIME_READINESS.md](./RESPONSE_TIME_READINESS.md).

## Demand forecasting

There is no ML demand model or bundled demand dataset. The backend
`DemandForecastService` is a transparent three-month recent-average baseline
over real database requests, with a one-month chronological holdout MAE
comparison when at least three months are available. Its output is explicitly
baseline-only and not a validated demand forecast.

The demand service uses request `createdAt` and normalized `bloodGroup`,
deduplicates stable request IDs, and does not expose patient or donor
information. Demand evaluation must be regenerated against a real request
history export; no accuracy is claimed from the response dataset.

## Shortage risk

Shortage risk is not an ML model. It is an authorized rule-based assessment
of unresolved requests versus currently available donors who pass the
application's eligibility and compatibility checks. It has no trained target,
temporal model, or predictive accuracy metric. It must not be described as a
validated shortage prediction.
